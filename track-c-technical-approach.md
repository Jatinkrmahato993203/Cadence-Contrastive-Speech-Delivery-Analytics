## 1. Dataset Construction Strategy (30% of score — build this first and best)

### 1.1 Source texts and GOOD-baseline audio: 8 passages, each 150-220 words (≈60-90s)

**Licensing design decision, stated up front:** famous political speeches delivered by their original speakers (FDR, JFK, Eisenhower, etc.) are tempting as "highly effective public speakers," but the *sound recording* of a 1940s-60s broadcast address is usually produced and held by the broadcasting network (NBC/CBS/etc.) or an archival institution, not created by a federal employee acting in that capacity — so 17 U.S.C. §105 (which exempts U.S.-government-authored works) covers the speech's *text*, not automatically the *recording*. Treating "the official said these words" as equivalent to "the recording is public domain" is exactly the kind of assumed-licensing shortcut the task warns against. Rather than ship a dataset whose core legal basis is "verify this later," we remove that ambiguity structurally: **all 6 historical-text GOOD recordings use LibriVox narrations**, which are categorically safe — LibriVox volunteer readers explicitly dedicate every recording to the public domain at the point of recording (stated on each recording's own catalog/license page), so there is no separate "is the *recording* itself cleared" question at all, independent of whether the underlying text is a government work, pre-1928 publication, or otherwise PD.

**Delivery-style screening, stated up front (this is a disclosed trade-off, not a denial):** a LibriVox volunteer reading a transcript for an audiobook catalog is optimized for clear, neutral narration, which is a different delivery style than the "effective public speaking" (rhetorical cadence, deliberate pause-for-emphasis, vocal stress tuned to persuade) that Requirement 1a is actually asking the GOOD baseline to capture. Licensing safety alone does not fix this, so Phase 0 includes an explicit screening step: for each of the 6 historical texts, pull every available LibriVox narration of that text (LibriVox frequently has 2-4+ independent readings of popular public-domain texts, and "Great Speeches"-style compilation projects exist on LibriVox specifically for dramatic/oratorical readings of historical speeches), listen to each candidate, and select the one with the most rhetorically-delivered performance — audible stress on key words, deliberate pauses at clause boundaries, a real pitch range rather than a flat monotone — over the most "neutral" one. Document the chosen reader and a one-line rationale per text in the dataset README. Where only one narration exists for a given text, that constraint and the resulting delivery-quality ceiling is stated explicitly in the README rather than silently accepted. The two original passages (#7-8) are self-recorded by team members after a short rehearsal pass aimed specifically at oratorical delivery (stress, pacing, pause placement) — not a cold read — giving the dataset at least two anchors that are performed oratory rather than narration by construction.

**Licensing verification is a required, scheduled action, not an assumption.** Picking "the most rhetorical" candidate and asserting LibriVox recordings are categorically PD is not itself proof for any *specific* chosen recording — the plan needs a concrete step that produces the evidence, not just the claim. So the screening step above is followed, for every one of the 6 chosen recordings, by a mandatory verification sub-step before that recording is locked in: open that exact recording's LibriVox catalog page, copy its explicit public-domain dedication statement verbatim, and record that statement plus the page's URL in a per-text citation table in the dataset README (`text_id, title, reader, librivox_url, license_statement_excerpt`). This is a checklist item in the Phase 0 timeline row (§6) with its own checkbox per text — a recording is not used in the dataset until its row in that table is filled in. If any candidate's catalog page is ambiguous or missing an explicit dedication statement, it is dropped in favor of the next rhetorical-delivery candidate, never used on the assumption that "it's LibriVox so it must be fine."

This gives **6 distinct LibriVox voices + 2 team members = 8 distinct human voices** in the GOOD set before any BAD variant is produced — the groundwork the speaker-agnostic normalization test in §2.3 needs to be a real test rather than a single-voice-per-text illusion of diversity.

This is explicitly non-load-bearing: nothing in the dataset's required 30%-weighted score depends on it.

Do **not** use TED, modern politicians, or "champion debater" recordings as source audio — their licenses (TED is CC BY-NC-ND, i.e. explicitly no-derivatives) forbid exactly the modification this project requires.

### 1.2 Recording/sourcing plan: realistic volume for 60 hours

For each of the 8 texts, produce:

- **1 GOOD recording**: the LibriVox or self-recorded audio above, trimmed to the chosen excerpt, 44.1kHz master retained, downsampled to 16kHz/16-bit mono for the processing/committed copy (see §1.4 for why).
- **7 BAD recordings**, forming the required gradient from egregious to near-perfect, one per mechanism below, produced by programmatic modification of that text's own GOOD audio (legal for all 8 texts: texts 1-6 are built on PD-dedicated recordings so modification is unrestricted, texts 7-8 are team-owned).

Total: 8 × 8 = **64 recordings**. At ~75-90s average excerpt length, that is ≈75-100 minutes of raw audio across all clips.

### 1.3 Concrete production method per flaw type, all three severity tiers specified, and the tier used for each produced recording made explicit

**Dependency note:** rows 3 and 5 below consume MFA word/phone timestamps as a direct input. Those timestamps must exist for all 8 GOOD clips *before* any flaw-generation script in this section is run — see the Phase 0 timeline fix in §6, which runs MFA on the 8 GOOD clips first, specifically so Phase 1 is never blocked waiting on them.

| # | Flaw category | Production method | Tool | Egregious | Moderate | Near-perfect |
|---|---|---|---|---|---|---|
| 1 | **Pacing** (too fast/slow) | Programmatic time-stretch of the GOOD recording, pitch-preserved | `librosa.effects.time_stretch` (phase-vocoder) | 0.65× or 1.5× | 0.75× or 1.3× | 0.85× or 1.15× |
| 2 | **Pitch / monotone** | Programmatic pitch-variance compression: shrink each word's F0 contour toward the clip's mean F0 by a fixed fraction | `parselmouth` (Praat `Manipulation` pitch-tier scaling) | compress variance to 10% of original | compress to 40% of original | compress to 70% of original |
| 3 | **Pauses** (missing/extra/misplaced) | Programmatic silence injection/removal at word boundaries taken from the GOOD recording's own forced-alignment timestamps (produced in Phase 0, see dependency note above) | `pydub` (`AudioSegment` splice) using MFA word timestamps (§2) as splice points | insert 2-3 unplanned pauses of 1.0-2.0s | insert 1 unplanned pause of 0.4-0.8s | insert one 0.2-0.3s pause |
| 4 | **Volume** (inconsistent/too quiet) | Programmatic gain envelope applied to a time window of the GOOD recording | `pydub` gain automation / `audiomentations.Gain` | -18dB over 30% of the clip | -10dB over 20% of the clip | -6dB over 10% of the clip |
| 5 | **Clarity/articulation** (mumbling, slurring) | Phone-boundary crossfade blending (merges adjacent MFA-aligned phones, timestamps from Phase 0, so transitions are no longer distinct) + STFT-magnitude spectral smoothing along the frequency axis (blurs/broadens formant peaks, the actual acoustic correlate of imprecise articulation) + transient softening on stop-consonant bursts (reduces plosive crispness) | `pydub` crossfade at MFA phone boundaries; `scipy.signal` boxcar convolution over `librosa.stft` magnitude (phase preserved) + `librosa.istft`; `pysndfx`/manual envelope-follower attack-softening on consonant segments | crossfade 70-90ms, 15-bin smoothing kernel, -8dB transient reduction | crossfade 40-60ms, 7-bin kernel, -4dB transient reduction | crossfade 15-25ms, 3-bin kernel, -2dB transient reduction |
| 6 | **Combined/egregious anchor** | Stack 2-3 of the above (e.g., fast pacing + monotone + missing pauses) on one clip | all of the above chained, egregious params | worst-case anchor, one per text | — | — |
| 7 | **Near-perfect anchor** | Single mildest perturbation from any one category | any one tool above at near-perfect param | — | — | best-case "flawed" anchor, one per text |

**Why row 5 is built this way (not a flat low-pass filter):** a flat Butterworth low-pass removes high-frequency content uniformly across the whole clip — that is the signature of a muffled microphone or bad codec (something between mouth and mic), not of a speaker's own imprecise articulation. Real mumbling/slurring comes from reduced formant transitions and under-articulated consonants while the overall spectral envelope shape and F0 stay broadly normal — a phonetic/temporal phenomenon, not a flat spectral rolloff. The method here targets that directly: crossfading across MFA phone boundaries literally merges adjacent sounds into each other (the acoustic definition of slurring words together); smoothing the STFT magnitude along the frequency axis blurs formant peaks without touching F0 or overall frequency balance (the actual acoustic correlate of "less precise articulation"); softening consonant transients reduces the crispness of plosive bursts specifically, rather than rolling off treble everywhere. All three are driven by MFA phone/word timestamps and are concretely tiered by crossfade duration, smoothing-kernel width, and transient-reduction dB.

**Tier actually used for the one produced recording in rows 1-5: MODERATE**, every time. This is fixed here so a team implementing the scripts never has to guess. The reasoning: rows 6 and 7 already commit to the egregious and near-perfect extremes respectively, so each flaw family only needs its row 1-5 recording to occupy the middle of the gradient to produce a true 3-point severity curve per category (near-perfect → moderate-single-flaw → egregious-combined). Concretely: the "pacing" BAD recording for a given text is made at 0.75×/1.3× (moderate), not 0.65×/1.5× or 0.85×/1.15×, and likewise moderate-tier parameters for pitch, pauses, volume, and clarity.

This gives, per text, a true gradient: GOOD → near-perfect → 5 moderate single-flaw variants → egregious combined, i.e., 8 ordered points per passage (1 GOOD + 7 BAD), 64 total.

### 1.4 Labeling, alignment-label verification, and sizing

- **Transcript labels**: identical text per good/bad pair (that's the contrastive design — same words, different delivery), stored as plain `.txt` + word list.
- **Flaw region ground truth**: every BAD clip is produced by a script with known parameters (which phones were crossfaded/smoothed, which words were time-stretched, which window got the gain cut, which silence was spliced in), so flaw region boundaries are **programmatically exact and known at generation time** — no manual annotation needed for any of the 56 BAD clips, since all 7 BAD mechanisms per text are script-driven.
- **Storage format**: one JSON per clip: `{clip_id, source_text_id, speaker_id, speaker_source (librivox|team), flaw_type, severity_tier, split (calibration|heldout, §1.5), flaw_regions: [{start_s, end_s, mechanism}], transcript_path, audio_path}`. (`speaker_source` has exactly two values for the required 8 texts; an optional bonus archival clip, if added per §1.1, gets its own `archival_bonus` tag and is excluded from the core speaker-source statistics in §2.3/§3.1.)
- **Sizing**: committed copies are 16kHz/16-bit mono — the native rate MFA's `english_us_arpa` model and most of the feature-extraction stack expect anyway, so no quality is lost for this pipeline. Size = 16,000 samples/s × 2 bytes/sample × 60 s/min ≈ 1.92MB/min. For 75-100 minutes total: **≈144-192MB**, comfortably inside GitHub's free Git LFS quota (1GB storage / 1GB bandwidth per month), committed directly under `/dataset/` — no external Drive link required. (44.1kHz masters, if kept, are stored only locally/in a linked Drive folder for reference, not committed.)

### 1.5 Calibration / held-out split (closes the "for testing" requirement, Req. 1c)

Requirement 1c asks the dataset to support both "training and testing" — every threshold and normalization statistic in a naive design would be computed from, and only ever evaluated against, the same clips, which gives no non-circular way to report an accuracy number for flaw-region timestamps. Fixed with an explicit split, decided in Phase 0 and written into the dataset JSON's `split` field:

- **Calibration set: 6 texts, 48 clips** — texts #1-5 (5 LibriVox) + text #7 (1 team original). All per-speaker-source-group thresholds (§3.1), pooled normalization statistics, and `config.yaml` constants are computed **only** from this set.
- **Held-out test set: 2 texts, 16 clips** — text #6 (LibriVox, Sojourner Truth) + text #8 (team original). These clips are never used to compute any threshold or statistic. They exist only to report accuracy: because every BAD clip's flaw region is exactly known at generation time (§1.4), the team computes **temporal IoU** (intersection-over-union of seconds) between each held-out clip's system-detected flaw region(s) and its known-injected ground-truth region, per flaw category, and reports mean IoU in the technical doc and as a dedicated "held-out evaluation" panel in the dashboard (§5). This is the number that actually answers the 25%-weighted "accuracy of flaw-region timestamps" criterion, instead of a generic unit test.
- **Disclosed limitation**: holding out one team-recorded text leaves exactly one team-recorded clip (~150-220 words) in the calibration set for estimating the `team` speaker-source-group threshold (§3.1) — i.e., an n=1-speaker estimate. This is stated explicitly in the README and surfaced in the dashboard as "team-group threshold calibrated on 1 speaker (lower confidence)" rather than hidden, since the dataset's small size makes a deeper split infeasible in a hackathon timeframe.

## 2. Forced Alignment & Feature Extraction Pipeline

### 2.1 Forced alignment — two toolchains, for two different environments

Alignment is split into an **offline/build-time** toolchain and an **online/runtime** toolchain, because the online dashboard's deployment target cannot run the offline tool (explained below):

- **Offline, for building the 64-clip dataset — Montreal Forced Aligner (MFA)**, open-source (MIT), CPU-only, the de facto standard research tool for text-to-audio forced alignment, installed via `conda`/`mamba` on team laptops and in GitHub Actions CI (both support conda runners). Use the pretrained **English (US) MFA acoustic model + pronunciation dictionary** (`english_us_arpa`), downloaded via `mfa model download`. Run MFA per clip: input = `(audio.wav, transcript.txt)` → output = TextGrid with word- and phone-level start/end timestamps.
  - **Scheduling, made explicit:** MFA is run on the **8 GOOD clips first, in Phase 0** (hours 0-4, §6) — before any flaw-generation script executes — because §1.3 rows 3 (Pauses) and 5 (Clarity) consume those GOOD-clip word/phone timestamps as a direct input to produce their BAD variants. A team that waits until "Phase 2: Alignment+features" to run MFA would be stuck writing pause/clarity flaw scripts with no timestamps to splice against. Running MFA on 8 short clips (≈75-100 minutes of audio total, but MFA runtime scales with corpus size and 8 clips align in well under 10 minutes on a laptop CPU) fits comfortably inside the Phase 0 window alongside the LibriVox screening/licensing work, since the two can run in parallel across team members.
  - Because the BAD-clip perturbations are known transformations of the GOOD clip's own MFA alignment (a time-stretch factor, a splice point, a gain window, a crossfade span are all explicit functions of the GOOD alignment), derive each BAD clip's ground-truth word timestamps analytically from the known transform rather than re-running MFA blind on deliberately degraded audio. This is fast, exact, and used only for building/validating the dataset itself.
  - **Verification (reproducibility requirement)**: automated sanity checks per clip — (a) total aligned span within 2% of true audio duration, (b) no negative-duration or overlapping word intervals, (c) aligned word count == transcript word count. Any dataset clip failing these is flagged and manually inspected in the MFA TextGrid viewer; this is a 20-line Python script, run in CI (GitHub Actions) on every dataset commit. This CI verification pass, plus the full-corpus re-check, is the part that lives in Phase 2 (§6) — distinct from the Phase 0 "run MFA on the 8 GOOD clips so flaw scripts have timestamps" step, which is a prerequisite for Phase 1, not a Phase 2 deliverable.
- **Online, for the deployed dashboard's arbitrary user-uploaded recordings (Requirement 4a)** — **WhisperX** (`whisperx`, open-source, pip-installable, CPU-capable with a small Whisper model, exposes per-word confidence from its wav2vec2-based alignment stage). This is the only aligner the live dashboard depends on, which is what makes the default Streamlit Community Cloud deployment actually runnable (§5):
  1. Run WhisperX alignment on the upload using the small model.
  2. Score alignment confidence per word from WhisperX's native per-word confidence output.
  3. If **any** word in the clip falls below a fixed percentile threshold (set once from the calibration-set GOOD corpus's own alignment-confidence distribution), **re-run the entire clip** — not an isolated span — with a larger WhisperX model size (`small` → `medium`, still CPU-feasible for a clip of ≤90s, adding roughly a few extra seconds of processing). This is deliberate: WhisperX's wav2vec2-based alignment stage aligns each word using its surrounding phonetic/acoustic context, so re-aligning a lone extracted snippet in isolation would remove exactly the context the aligner needs and make the result worse, not better; re-running the full clip keeps that context intact.
  4. The medium-model run's output **fully replaces** the small-model run's output for the whole clip — there is no per-word merge or reconciliation between the two runs. The small-model run is used only as a trigger ("is a retry needed at all?"), never blended with the retry's timestamps.
  5. Any word that remains below the confidence threshold after the medium-model retry is surfaced in the dashboard as an explicit "alignment uncertain in this region" annotation (grey hatching on the time-series overlay) instead of being fed into flaw-grounding as if it were a confident timestamp. (The `[STRETCH]` Docker deployment, which can bundle MFA, instead uses MFA as a third, highest-precision fallback for teams who want the extra accuracy — not required for the default path.)

### 2.2 Feature extraction

Computed per word-level segment (from the relevant aligner's timestamps) and as continuous contours:

| Feature | Library/method | Purpose |
|---|---|---|
| MFCCs (13 coeffs + Δ + Δ²) | `librosa.feature.mfcc` | timbral/clarity footprint |
| STFT / spectrogram, spectral centroid, spectral flatness | `librosa.stft`, `librosa.feature.spectral_centroid/flatness` | FFT-based acoustic footprint, clarity proxy |
| F0 contour | `parselmouth` (Praat Python binding, via `praat-parselmouth`) `To Pitch` | pitch/intonation |
| Jitter, shimmer, HNR (harmonics-to-noise ratio) | `parselmouth` voice-report functions | vocal clarity/stability — standard Praat voice-quality metrics |
| RMS energy / loudness | `librosa.feature.rms` + `pyloudnorm` (ITU-R BS.1770 loudness) | volume |
| Speech rate | words-per-second from aligner word boundaries | pacing |
| Pause intervals | gaps between aligner word end/next word start > 150ms | pause detection |

All of this runs in well under a second per clip on a CPU; the full 64-clip corpus extracts in under 2 minutes — no GPU needed anywhere in this stage. `praat-parselmouth` ships prebuilt wheels and is pip-installable, consistent with the online-path constraint in §2.1/§5.

### 2.3 Speaker-agnostic normalization, implemented *and* actually exercised across distinct speakers

Raw F0 and energy differ hugely by speaker biology, so comparing raw Hz/dB across speakers is invalid. Concrete normalization:

- **Pitch**: convert every F0 value to **semitones relative to that speaker's own median F0 across all their recordings**: `ST = 12 * log2(F0 / F0_median_speaker)`.
- **Energy/volume**: normalize with `pyloudnorm` to a common target loudness (-23 LUFS, EBU R128) at the file level, then express in-clip volume deviations as **dB relative to that same speaker's own 95th-percentile RMS**, not an absolute dB floor.
- **Speech rate**: express as **z-score relative to that speaker's own mean words-per-second**.
- **New-speaker bootstrap, mode-agnostic (fixes the gap where only rate had a fallback):** for *any* speaker with zero prior recordings in the system — whether that's a general-mode upload (§3.0 Mode B) or a judge/team-member re-recording a bundled passage in paired mode (§3.0 Mode A) — the per-speaker median F0, 95th-percentile RMS, and mean words-per-second used in the three formulas above are **all** bootstrapped the same way: computed from that speaker's own first ~10 words in the current clip, then refined online (recomputed as a running statistic) as more of the clip is processed. This applies identically to pitch, energy, and rate — not just rate — so a re-recording team member in Mode A (who by definition has no prior history) has the same concrete formula as a first-time Mode B uploader, rather than an undefined case. If a returning speaker already has prior clips on file, their accumulated median/percentile/mean across *all* their recordings is used instead of the single-clip bootstrap.
- **Comparison mechanic**: because every bundled pair shares the identical transcript, word-level alignment lets you compare GOOD-clip-word-*i* to BAD-clip-word-*i* directly (no DTW needed) for the dataset's own clips. Deltas are computed in normalized units (semitones, loudness-relative dB, rate z-score) per word.
- **Why this is actually tested, not just asserted**: §1.1-1.2 deliberately put **6 distinct LibriVox narrators + 2 team members = 8 distinct real speakers** into the GOOD baseline set itself, rather than one voice per text DSP-edited into variants. A required unit test (added to the repo's test suite, run in Phase 2/CI) computes each of these 8 speakers' median F0 and 95th-percentile RMS independently — using all 8 GOOD clips, since this test checks the normalization formula itself rather than any flaw-detection threshold, so the calibration/held-out split in §1.5 does not apply here — and verifies that a high-pitched speaker's *normal, unflawed* delivery does not get flagged as a pitch-deviation outlier relative to a low-pitched speaker's baseline once both are expressed in semitone/relative-dB space. This is the concrete, falsifiable check that makes "speaker-agnostic" a tested property instead of a claim.

## 3. Temporal Flaw Grounding & Causal Explanation

### 3.0 Two comparison modes — because the dashboard must handle arbitrary uploads, not just the bundled 8 texts

Requirement 4a requires the dashboard to "accept audio and transcript uploads" in general, not just the team's own bundled passages. Word-for-word index comparison (as used within the dataset itself) is only well-defined when the uploaded transcript actually matches one of the 8 bundled texts — for anything else, there is no paired baseline with identical words to index against. The pipeline therefore runs in one of two modes, chosen automatically per upload:

- **Mode A — Paired mode.** Triggered when the uploaded transcript exactly matches one of the 8 bundled transcripts (after lowercasing/punctuation-stripping), or has ≥90% token-level overlap with one of them (computed with a simple Jaccard or Levenshtein-ratio check against each of the 8 stored transcripts — a concrete, operational rule, not a vague "nearest match"). This covers judges/testers trying the bundled sample texts, or a team member re-recording a bundled passage (using the mode-agnostic new-speaker bootstrap from §2.3 for that re-recording case). Grounding proceeds exactly as in §3.1 below: direct word-index delta against the matched GOOD baseline, using that baseline's speaker-source-group threshold from the **calibration set** (§1.5) — if the match is to a held-out text, the dashboard still scores it (that's the point of §1.5) but labels the result "held-out evaluation example" rather than "calibration example."
- **Mode B — General mode.** Triggered for everything else — any arbitrary speech + transcript that does not match a bundled text, which is the actual required behavior for Requirement 4a. Here there is no paired baseline to diff against word-by-word, so the comparator changes:
  1. Run WhisperX alignment on the upload (§2.1) to get its own word-level timestamps.
  2. Compute the same per-word normalized features as §2.2-2.3 (semitone-relative pitch, loudness-relative dB, local rate z-score, pause flags, clarity/HNR) — using the speaker's own running statistics bootstrapped from the first ~10 words of the uploaded clip itself (§2.3), since there's no prior recording of this speaker.
  3. Because these features are already speaker-identity-free by construction (that is the entire point of §2.3's normalization), a word can be flagged as deviant by comparing its normalized value directly against the **pooled calibration-set GOOD distribution for that feature** (mean/SD computed once across all 6 calibration-set GOOD clips' word-level normalized values, §3.1) — no paired word is needed, because the normalization already did the speaker-agnostic work.
  4. **Threshold consistency fix**: the flag/no-flag cutoff applied in Mode B is the SD of that *same* pooled-all-calibration-speakers distribution (not a narrower subgroup's SD) — see §3.1 for why this must match the population the mean/SD reference itself was computed from.
  5. Grounding (merging contiguous deviant words into regions, §3.1 steps 4-5) works identically in both modes; only the comparator differs.
  6. Dashboard overlay (§5) in Mode B renders the uploaded clip's contour against a shaded **normative corridor** (pooled calibration-GOOD mean ± threshold band per feature, time-normalized to 0-100% of clip duration since there is no absolute word-index alignment across different texts), instead of Mode A's exact paired curve.
  7. This is explicitly tested, not just designed: Phase 5 of the timeline (§6) budgets testing against 2-3 fresh, unseen, non-bundled speeches specifically to exercise Mode B end-to-end.

### 3.1 Grounding method (rule-based, deterministic — chosen deliberately)

1. Determine mode (§3.0). In Mode A, align word-for-word against the matched GOOD baseline; in Mode B, align against the pooled calibration-set normative distribution.
2. At each word index, compute the normalized deltas: Δpitch (semitones), Δenergy (relative dB), Δrate (local z-score over a 3-word sliding window), pause-presence flag, Δclarity (MFCC cosine distance / HNR delta) — against the paired word (Mode A) or the pooled calibration distribution (Mode B).
3. **Threshold definition, made explicit (fixes both the undefined-quantity and the mismatched-population issues):**
   - For each normalized feature *f*, define `sigma_group(f)` = the sample standard deviation of feature *f*'s **per-word value, pooled across every word in every calibration-set GOOD clip in the group** — e.g. for the `librivox` group, pool the semitone-from-own-median value of every word across the 5 calibration-set LibriVox GOOD clips (≈750-1100 words) and take its SD; likewise for `team` (1 calibration-set clip, ≈150-220 words — the n=1-speaker limitation disclosed in §1.5). Since a GOOD clip's own words have no separate baseline to delta against, this per-word normalized value *is* the natural "how much does a clean word vary from this speaker's own median" quantity, which is exactly the "normal variation" the threshold needs to be calibrated on.
   - **Mode A** flags a word as "deviant" if any |Δ| (computed against the matched GOOD baseline word, step 2) exceeds `1.5 × sigma_group(f)`, using whichever group (`librivox`/`team`) the matched baseline belongs to.
   - **Mode B** flags a word as "deviant" if any |Δ| (computed against the pooled calibration-set mean, step 2 / §3.0 step 3) exceeds `1.5 × sigma_pooled_all(f)`, where `sigma_pooled_all(f)` is the SD of feature *f* pooled across **all 6 calibration-set GOOD clips together** (not a subgroup) — the same population the Mode B mean/SD reference itself was built from. This avoids mismatching a word's deviation, measured against the full pooled-speaker mean, against a narrower subgroup's spread as the cutoff.
   - All of `sigma_group(f)` and `sigma_pooled_all(f)`, per feature, are computed once and checked into `config.yaml`.
4. **Temporal grounding** = contiguous runs of ≥2 consecutive deviant words (using the aligner's own word start/end timestamps, or the retry-path timestamps where confidence was low per §2.1) as the region's start/end — down to roughly ±20-30ms resolution where alignment confidence is high, explicitly flagged as uncertain where it is not.
5. Merge overlapping/adjacent regions (gap < 200ms) into one region.

This is a **rule-based, fully deterministic** method — same input always produces the same output, satisfying the reproducibility criterion (10%) and requiring zero training data or GPU. A trained statistical/ML flaw-detector would need labeled training data at a scale the 64-clip corpus cannot responsibly provide for training (it is sized for calibration, held-out evaluation, and demo — see §1.5), so rule-based-on-normalized-deltas is the correct choice given the time and compute constraints.

### 3.2 Causal explanation mechanism (hybrid, bounded for reproducibility)

- **Deterministic core**: a template engine maps each (feature, direction, magnitude) triple to a structured explanation string, e.g.:
  > "Speech rate was 38% faster than baseline (4.1 words/s vs. 2.9 words/s) across 'and so my fellow Americans', compressing stressed syllables and causing the F0 peak that normally lands on 'fellow' to be missed; HNR dropped 4.2dB in the same span, consistent with clarity loss under rushed articulation."

  This string is built entirely from the numeric deltas computed in §3.1/§2.3 — every clause cites a real number from the pipeline. One template per flaw category, parameterized by the actual magnitudes. In Mode B, "baseline" in the template text is phrased as "the expected range for this feature" rather than a specific paired clip's value, since there is no single paired recording.
- **Optional LLM polish [non-load-bearing]**: pass the *same* structured JSON (feature, delta, region words) to an LLM call at temperature 0 purely to smooth the template sentence's prose — never to invent the numbers. If the LLM call fails, is rate-limited, or is skipped for the demo, the deterministic template string is shown unchanged.

## 4. Scoring / Rubric Methodology

- Define 5 rubric dimensions matching the flaw taxonomy: Pacing, Pitch/Intonation, Pauses, Volume, Clarity. Each scored 0-20 (100 total), deterministically:

  ```
  if dimension has zero flagged regions:
      severity_weight = 0          # explicit base case — no deviation means no severity
  else:
      severity_weight = mean(|Δ|_normalized across that dimension's flagged regions)  # bounded 0-1, §3.1 saturation constant

  dimension_score = 20 * (1 - clamp(total_flawed_duration_in_region / total_clip_duration, 0, 1) * severity_weight)
  ```

  **Why the explicit base case is required:** `severity_weight` is "the mean |Δ| across that dimension's flagged regions," and a mean over an empty set (`numpy.mean([])`) is NaN, not 0. Under IEEE-754, `0 * NaN = NaN`, so without the explicit `severity_weight = 0` base case, the formula silently produces `dimension_score = NaN` on the single most common case — every clean dimension, including every GOOD clip and every near-perfect clip, and specifically all 48 calibration-set GOOD clips the pipeline's own normalization statistics are computed from. With the base case in place, a clean dimension (zero flagged regions, zero flawed duration) correctly collapses to `dimension_score = 20 * (1 - 0 * 0) = 20`, i.e. a perfect score, which is the intended behavior. This base case ships with its own unit test (`test_score_zero_regions`) asserting `dimension_score == 20` and `not math.isnan(score)` for an all-clean input, run in CI alongside the reproducibility test below.
- Overall score = sum of 5 dimension scores (0-100), plus the list of flaw regions + causal explanations (and any alignment-uncertain spans, and the mode — A or B — used) as supporting evidence, kept visible for transparency rather than folded into the number.
- **Reproducibility guarantee**: all thresholds/weights are fixed constants computed once from the calibration-set GOOD clips and checked into the repo as `config.yaml`. Given the same audio+transcript input, the pipeline is a pure function — verified explicitly with a `make reproducibility-test` CI step that re-runs the pipeline twice and diffs the JSON output.

## 5. Dashboard Architecture

- **Stack**: Python-only — **Streamlit** (frontend+light backend in one framework) + **Plotly** for interactive time-series charts, deployable on Streamlit Community Cloud's free tier. This is consistent with the runtime dependency chain: the live aligner is **WhisperX only** (§2.1), which is pip-installable, so `requirements.txt` + a `packages.txt` entry for `ffmpeg` (apt-installable, which Streamlit Community Cloud's build system does support) is sufficient — no conda step is needed at deploy time. MFA (conda-only) is used solely offline/in CI to build the committed dataset, never by the deployed app.
- **Flow**: user uploads `(audio_file, transcript_text)` → mode detection (§3.0: Mode A vs Mode B) → WhisperX alignment with the confidence-scored whole-clip retry path from §2.1 → feature extraction (§2.2) → normalization (§2.3, including the mode-agnostic new-speaker bootstrap) → grounding + explanation (§3) using the matched baseline (Mode A) or pooled normative corridor (Mode B) → scoring (§4, with the zero-flag base case) → results rendered, with any low-confidence alignment spans carried through and shown as "uncertain" rather than dropped silently.
- **UI contents**:
  1. Waveform + aligned word boundaries (from WhisperX) shown as a ruler under the audio player, with uncertain spans visually distinct (hatched).
  2. **Time-series overlay**: in Mode A, the matched GOOD baseline's normalized pitch/energy/rate contours plotted against the uploaded clip's on the same time axis (Plotly multi-trace line chart); in Mode B, the uploaded clip's contour plotted against the shaded pooled normative corridor (§3.0). A small badge indicates which mode was used and why (exact/near match found, or no match → general mode), and whether a Mode A match landed on a calibration or held-out text.
  3. Flagged flaw regions rendered as shaded vertical bands, click-to-expand to show the causal explanation text (§3.2) and the dimension scores affected.
  4. A rubric scorecard (5 bars, §4) plus overall score, with a "re-run" button that proves determinism.
  5. **Held-out evaluation panel** (§1.5): a static, pre-computed view showing mean temporal-IoU accuracy per flaw category on the 2 held-out texts' 14 BAD clips, against their known-injected ground truth — the concrete evidence for the "accuracy of flaw-region timestamps" criterion.
- **Backend processing**: synchronous, in-process (clips are ≤90s, full pipeline runs in a few seconds on CPU).
- **[STRETCH]** package as a Docker image (`Dockerfile` + pinned `requirements.txt`/`environment.yml` including `mfa`, `whisperx`, `parselmouth`, `librosa`, `streamlit`, `plotly`) for teams who want MFA-quality alignment available in the live demo too — deployment is literally `docker build && docker run`, but this is additive, not required to meet the deliverable.

## 7. Risks & Mitigations

| Risk | Why it happens | Mitigation |
|---|---|---|
| Dataset too small/clean to be convincing | 64 clips, scripted flaws, 8 texts | Document the exact injection recipe and parameters per clip (incl. which tier each produced recording uses, §1.3) in the dataset README so judges see a reproducible, extensible method, explicitly framed against the brief's own "quality over quantity" priority, plus a genuine held-out accuracy number (§1.5) rather than only self-reported design claims. |
| Forced alignment fails/degrades on badly-flawed *uploaded* audio | The online aligner's model is trained on normal speech; severe or unknown flaws push it out-of-distribution | Confidence-scored two-pass alignment (WhisperX small → WhisperX medium whole-clip retry, or MFA in the stretch Docker path) with explicit "uncertain" surfacing in the dashboard rather than a silently-wrong timestamp (§2.1, §5). Tested end-to-end on fresh unseen recordings in Phase 5. |
| Dashboard has no defined behavior for an arbitrary (non-bundled) upload | The only comparator originally built was word-index diffing against a paired baseline, which is undefined for mismatched text | Explicit Mode A (paired, matched-transcript) / Mode B (general, pooled-normative-range, consistently-thresholded) split (§3.0), reusing the already-speaker-agnostic normalized features from §2.3; Mode B specifically tested on fresh non-bundled speeches in Phase 5. |
| Causal explanations are plausible-sounding but not grounded | Easy trap if using an LLM to "explain" without passing it real numbers | Explanation templates are built directly from the same numeric deltas used for grounding (§3.2) — never a free-text LLM guess. Unit-test: for each synthetically-injected flaw (ground truth exactly known), assert the detected region and explanation cite that same feature/magnitude/time window within tolerance; the held-out IoU metric (§1.5) is the non-circular version of this check. |
| Copyright/licensing issues with "prominent" speeches | Brief suggests TED/politicians, which carry restrictive licenses, and even speeches by federal officials raise a separate question about who owns the *recording* | All 8 required GOOD clips are built on LibriVox readings (categorically PD-dedicated recordings, independent of any broadcast-rights question, with a mandatory per-recording verification checklist logging the exact dedication statement and URL, §1.1) or team-owned originals; any archival "famous voice" clip is strictly optional and gated behind an explicit recording-vs-text copyright checklist (§1.1), never load-bearing for the required score. |
| GOOD baselines sound like narration rather than oratory | LibriVox readers default to neutral audiobook delivery, which differs from persuasive-speech cadence | Explicit per-text screening across multiple available LibriVox narrations for rhetorical delivery, documented rationale per pick in the README (§1.1), plus two team-performed originals rehearsed specifically for oratorical delivery as a non-narration anchor. Disclosed as a known trade-off, not asserted away. |
| Online dashboard can't actually run its own alignment dependency | MFA is conda-only; the default free-tier deploy target has no conda build path | Runtime aligner for the deployed app is WhisperX (pip-installable, works with Streamlit Community Cloud's `requirements.txt`/`packages.txt`); MFA is confined to offline dataset-building/CI, never a deploy-time dependency (§2.1, §5). |
| Flaw-detection thresholds/stats are calibrated and evaluated on the same clips | No held-out split means no non-circular accuracy number for the 25%-weighted grounding criterion | Explicit 6-calibration/2-held-out text split (§1.5); held-out clips never touch threshold or normalization computation and are used only to report mean temporal IoU against known-injected ground truth, surfaced in both the doc and a dashboard panel. |
| Deviance threshold miscalibrated by mixing populations inconsistently | Comparing a word's deviation against one population's mean while flagging it with a different, narrower population's spread invalidates the cutoff | Mode A uses one speaker-source group's mean+SD together; Mode B uses the full pooled-calibration-speaker mean+SD together (§3.1) — reference and threshold are now always drawn from the same population, with the exact pooled quantity ("per-word normalized value, pooled across every word in the relevant calibration clips") spelled out explicitly rather than left for the implementer to guess. |
| Score formula returns NaN on the (most common) zero-flag case | `mean()` over an empty set of flagged regions is undefined, and `0 * NaN` does not short-circuit to 0 under IEEE-754 | `severity_weight` has an explicit `= 0` base case when a dimension has zero flagged regions (§4), covered by a dedicated unit test asserting a clean dimension scores 20 and is never NaN. |
| Flaw-generation scripts block on timestamps that don't exist yet | Pause/clarity flaw scripts need MFA word/phone timestamps as direct inputs, but a naive schedule runs full-corpus alignment after dataset-sprint work has already started | MFA is run on the 8 GOOD clips specifically inside Phase 0 (§6), before Phase 1's flaw scripts start; full-corpus CI verification is scheduled separately in Phase 2 and does not block Phase 1. |
| Licensing claim has no corresponding verification action | Asserting "LibriVox recordings are PD-dedicated" in general doesn't verify any *specific* chosen recording without someone checking its actual catalog page | Per-recording licensing verification is a required Phase 0 checklist item (§1.1): each of the 6 chosen recordings' PD-dedication statement and URL are copied into a dataset README citation table before that recording is used; an ambiguous or missing statement disqualifies the candidate. |
| Mode A re-recording case has no defined speaker-normalization formula | Only speech rate had a stated new-speaker fallback; pitch/volume were undefined for a zero-history speaker re-recording a bundled passage in Mode A | The first-~10-words bootstrap for median F0, 95th-percentile RMS, and mean rate is made mode-agnostic (§2.3): it applies to any new speaker, in either Mode A or Mode B, not just Mode B uploads. |
| WhisperX retry step ambiguous between isolated-span and whole-clip re-alignment | Re-aligning an isolated span removes the phonetic context wav2vec2 needs, and re-running the whole clip raises an unaddressed merge question | Retry is specified as a full-clip re-run with the larger model whose output fully replaces the small-model run for that clip — no span isolation, no partial merge (§2.1). |
| Reproducibility breaks because of floating-point/library version drift | Different librosa/numpy/WhisperX versions can shift feature values slightly | Pin all versions in `requirements.txt`/`environment.yml`; the reproducibility test compares region boundaries and rubric scores, not raw floats; document exact versions in the 6-page doc. |
| Team runs out of time and dashboard is empty | Dashboard is 15% but often gets squeezed last | Build Streamlit skeleton with dummy/placeholder data in Phase 0-1 in parallel, wire in real pipeline output incrementally. |
| MFA/WhisperX install friction mid-hackathon | MFA ships via conda and needs model downloads over network; WhisperX needs a Whisper model download | Install and smoke-test both in Phase 0 (hour 0-4); pin exact versions in `environment.yml`/`requirements.txt`; keep pre-downloaded models committed to a shared drive as a wifi fallback. |
